Lasso lag fix notes

The main lag is not the gesture recognizer anymore. The real bottleneck is the live preview architecture: during drag, the app still rebuilds selected strokes into a new PKDrawing and pushes that drawing back into PKCanvasView repeatedly.

This document summarizes what to inspect, why it lags, and the fix path that should actually make the lasso feel native.

Main culprit

The expensive step is repeated full drawing replacement in PencilKit during live preview.

The hot path currently goes like this:

  1. The lasso drag in BlockOverlayView.swift calls beginLassoMovePreview() and updateLassoMovePreview(...).
  2. CanvasViewModel.swift rebuilds selected PKStroke values with a translated transform.
  3. Those strokes are packed into a new PKDrawing.
  4. forceDrawingPreviewRefresh triggers PKCanvasRepresentable.updateUIView(...).
  5. Coordinator.setDrawing(...) assigns canvas.drawing = drawing.

That means the preview is still using real drawing mutation as the movement preview. Even with throttling, this remains much heavier than moving a visual layer.

What to inspect

Area What to look for Why it matters
BlockOverlayView.swift The lasso drag handler calling updateLassoMovePreview(...) on every drag step. This is the entry point of the live preview loop.
CanvasViewModel.swift The code that recreates translated PKStroke values and wraps them in a new PKDrawing. This is the CPU-side rebuild cost.
PKCanvasRepresentable.swift The preview-refresh branch in updateUIView(...) and the call to setDrawing(...). This is the expensive handoff into PencilKit.
Coordinator.setDrawing(...) The assignment canvas.drawing = drawing. This is the single most expensive step in the live path.

Secondary contributors

Stroke rebuild cost

Every preview step loops through selected stroke indices and creates new PKStroke instances. Large selections multiply this cost quickly.

Overlay refresh cost

The lasso box and menu positions are also being recomputed while the preview is running. That is not the main bottleneck, but it adds extra work on top.

Preview cadence

The recent throttling helps, but it only reduces frequency. It does not remove the expensive operation itself.

What will not fix it

  • More drag gesture tweaks alone
  • More coordinate-space tweaks alone
  • Animation tuning alone
  • Minor threshold changes alone

Those help wobble and responsiveness at the edges, but they do not remove the architectural cost of replacing the drawing during preview.

Recommended fix

Use a lightweight visual preview while dragging, and commit real PencilKit mutation only on release.

The fix should separate preview from commit.

During drag

  • Do not call canvas.drawing = ... repeatedly.
  • Render the selected strokes as a temporary bitmap or overlay layer.
  • Move that preview layer and the lasso box together.
  • Optionally hide or dim the original selected strokes while previewing.

On release

  • Apply the final transform once to the real selected strokes.
  • Update the real PKDrawing once.
  • Persist and clear the preview overlay.

Implementation outline

  1. At lasso selection time, generate a preview image for the selected strokes using the existing selection screenshot/render path.
  2. Store preview state in CanvasViewModel.swift:
    • preview image
    • preview origin rect in canvas space
    • live translation during drag
  3. Render that preview inside the canvas-attached overlay layer, not as a full PencilKit redraw.
  4. While dragging, update only:
    • preview translation
    • lasso box
    • UI pills
  5. On drag end, mutate the real strokes and elements once, then remove the preview.

Validation checklist

  • Move a small lasso selection and check whether the preview stays under the finger without stutter.
  • Move a large lasso selection and confirm performance degrades far less than today.
  • Confirm undo/redo still works after final drop.
  • Confirm selected elements and selected strokes remain visually aligned during preview and after commit.
  • Confirm panning and zooming still behave normally with an active lasso selection.

Bottom line

The culprit is the repeated PKDrawing rebuild and canvas.drawing replacement during lasso preview. The fix is to stop using real PencilKit mutation as the drag preview and switch to a lightweight temporary overlay preview, then commit the actual drawing change once at the end.
